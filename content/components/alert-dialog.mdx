## Installation

**Command**

```install
npx shadcn@latest add @cadence/alert-dialog
```

This also installs `button`, which the two actions render through.

**Manual**

[Manual installation files](https://cadence.dev/r/alert-dialog.json)

Copy all ten target files, keeping `alert-dialog/index.tsx`, `button/index.tsx`
and the shared `lib/` directory in the same `cadence/` tree. Preserve the
relative imports and the sources' `"use client"` directives. Button reaches
`press-button.tsx`, which imports `control-animation.tsx` and in turn
`native-div.tsx`; copy every file in the provider, motion and utilities
payloads. The provider files and `motion` package remain required imports
even when you omit the optional provider wrapper.

Complete the base theme setup linked above and ensure Tailwind scans the
copied files. Include the Cadence easing and motion-scale tokens used by the
popup classes. There is no additional item-specific CSS or external asset.
The overlay fades and the panel fades and scales in full; reduced keeps
opacity only, and none removes the transitions and hidden entry styles.
Each portalled surface resolves its own provider clock. Standalone components
follow the system motion preference; an optional `CadenceProvider` controls
a subtree, and nested full still respects system reduced motion. The included
Button retains its own press-feedback contract.

Usage, Confirmation sizes and With an icon import `Trash2Icon`; the top
specimen uses it too. To copy those snippets unchanged, also install:

```package-manager
npm install lucide-react
```

An icon is optional for the component. Controlled, A confirmation that is
still working and Explicit motion scopes need no additional package or
registry item. Button and `CadenceProvider` are already included above.
The site's preview shell is not consumer setup.

In Next.js App Router, Usage, Confirmation sizes, With an icon, Controlled,
the pending example and the top specimen need a caller client module for
their `useState` and event handlers. Explicit motion scopes contains only
serializable JSX and element-valued `render` props, so it can be composed in
a synchronous Server Component. Caller refs, event handlers, function-valued
`render`, `className(state)` or `style(state)` also need a caller client
boundary. Synchronous `useId` alone does not require one. Preserve the
installed sources' client directives.

Place the trigger and content within the same `AlertDialog` root. The root
supports uncontrolled `defaultOpen`, or controlled `open` / `onOpenChange`;
it remains modal and ignores outside pointer presses. `AlertDialogContent`
already renders its portal, overlay and popup, so do not add another portal
or overlay around it. It accepts popup props such as `initialFocus` and
`finalFocus`; `size` defaults to `"default"`, with `"sm"` for the compact
layout. The separately exported Portal and Overlay are for custom composition.

Always include `AlertDialogTitle` for the accessible name and use
`AlertDialogDescription` for the consequence. Base UI associates them with
the alert dialog and manages focus trapping, scroll locking and Escape.
Keep Cancel first in DOM order so keyboard and mouse opening initially focus
the safe choice; touch opening can focus the popup itself. Default focus return
uses the trigger; when opening from an
external control, keep a suitable return target or supply `finalFocus`.
Mark a decorative media icon `aria-hidden="true"`. Custom Base UI `render`
elements must preserve the supplied props and ref; `render={<Button />}`
does not need an extra wrapper or `asChild`.

`AlertDialogCancel` renders Base UI Close through Button and closes
automatically; its defaults are `variant="outline"` and `size="default"`.
`AlertDialogAction` renders Button and leaves the dialog open. Use controlled
state to close after the caller's operation succeeds. Neither button performs
the destructive operation for you. In the pending example, the caller disables
both decision buttons, sets `aria-busy`, and rejects close requests while
pending; Complete request only resolves a local simulation. The caller owns
authorization, request execution, pending/error/retry UI, dismissal policy,
result announcements and persistence. The component adds no validation or
automatic form submission.

## Usage

```tsx
"use client";

import { Trash2Icon } from "lucide-react";
import { useState } from "react";
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogMedia,
  AlertDialogTitle,
  AlertDialogTrigger,
} from "@/components/cadence/alert-dialog";
import { Button } from "@/components/cadence/button";

export function Confirmation({ size = "default", withIcon = false }: { size?: "default" | "sm"; withIcon?: boolean }) {
  const [open, setOpen] = useState(false);
  const [deleted, setDeleted] = useState(false);
  return (
    <div className="flex flex-col items-start gap-3">
      <AlertDialog open={open} onOpenChange={setOpen}>
        <AlertDialogTrigger render={<Button variant="outline" />}>
          {size === "sm" ? "Archive" : "Delete project"}
        </AlertDialogTrigger>
        <AlertDialogContent size={size}>
          <AlertDialogHeader>
            {withIcon && (
              <AlertDialogMedia>
                <Trash2Icon aria-hidden="true" />
              </AlertDialogMedia>
            )}
            <AlertDialogTitle>{size === "sm" ? "Archive this project?" : "Delete this project?"}</AlertDialogTitle>
            <AlertDialogDescription>
              {size === "sm"
                ? "It stops deploying. You can unarchive it later."
                : "Every deployment and its logs go with it. This cannot be undone."}
            </AlertDialogDescription>
          </AlertDialogHeader>
          <AlertDialogFooter>
            <AlertDialogCancel>{size === "sm" ? "Cancel" : "Keep project"}</AlertDialogCancel>
            <AlertDialogAction
              variant={size === "sm" ? "default" : "destructive"}
              onClick={() => {
                setDeleted(true);
                setOpen(false);
              }}
            >
              {size === "sm" ? "Archive" : "Delete project"}
            </AlertDialogAction>
          </AlertDialogFooter>
        </AlertDialogContent>
      </AlertDialog>
      <p role="status" className="text-sm text-muted-foreground">
        {deleted ? (size === "sm" ? "Project archived locally" : "Project deleted locally") : "No changes"}
      </p>
    </div>
  );
}
```

## Controlled

The external opener sets caller-owned open state. Revoke key records a local result and closes explicitly. A production caller would close when its own operation completes; AlertDialogAction does not close automatically.

<ComponentExample name="controlled" />

```tsx
"use client";

import { useState } from "react";
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
} from "@/components/cadence/alert-dialog";
import { Button } from "@/components/cadence/button";

export function ControlledConfirmation() {
  const [open, setOpen] = useState(false);
  const [confirmed, setConfirmed] = useState(false);
  return (
    <div className="flex flex-col items-start gap-3">
      <Button variant="outline" onClick={() => setOpen(true)}>
        Request key revocation
      </Button>
      <AlertDialog open={open} onOpenChange={setOpen}>
        <AlertDialogContent>
          <AlertDialogHeader>
            <AlertDialogTitle>Revoke this key?</AlertDialogTitle>
            <AlertDialogDescription>Services using it lose access. Create a replacement first.</AlertDialogDescription>
          </AlertDialogHeader>
          <AlertDialogFooter>
            <AlertDialogCancel>Keep key</AlertDialogCancel>
            <AlertDialogAction
              variant="destructive"
              onClick={() => {
                setConfirmed(true);
                setOpen(false);
              }}
            >
              Revoke key
            </AlertDialogAction>
          </AlertDialogFooter>
        </AlertDialogContent>
      </AlertDialog>
      <p role="status" className="text-sm text-muted-foreground">
        {confirmed ? "Key revoked locally" : "Key active"}
      </p>
    </div>
  );
}
```

## A confirmation that is still working

The caller owns pending and disables both decision buttons while working. This example deliberately has no request: Complete request resolves the local simulation. The controlled root rejects Escape while pending; before pending, Escape and Cancel work normally. Keep this policy and an error/retry path in application code.

<ComponentExample name="pending" />

```tsx
"use client";

import { useState } from "react";
import {
  AlertDialog,
  AlertDialogAction,
  AlertDialogCancel,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogTrigger,
} from "@/components/cadence/alert-dialog";
import { Button } from "@/components/cadence/button";

export function PendingConfirmation() {
  const [open, setOpen] = useState(false);
  const [pending, setPending] = useState(false);
  const [complete, setComplete] = useState(false);
  return (
    <div className="flex flex-col items-start gap-3">
      <AlertDialog
        open={open}
        onOpenChange={(next) => {
          if (!pending) setOpen(next);
        }}
      >
        <AlertDialogTrigger render={<Button variant="outline" />}>Delete draft</AlertDialogTrigger>
        <AlertDialogContent>
          <AlertDialogHeader>
            <AlertDialogTitle>Delete this draft?</AlertDialogTitle>
            <AlertDialogDescription>
              This local example models a caller-owned request. Complete request resolves it without sending data.
            </AlertDialogDescription>
          </AlertDialogHeader>
          <p role="status" className="text-sm">
            {pending ? "Deletion pending" : "Ready to delete"}
          </p>
          <AlertDialogFooter>
            <AlertDialogCancel disabled={pending}>Keep draft</AlertDialogCancel>
            <AlertDialogAction
              variant="destructive"
              disabled={pending}
              aria-busy={pending}
              onClick={() => setPending(true)}
            >
              {pending ? "Deleting…" : "Delete draft"}
            </AlertDialogAction>
          </AlertDialogFooter>
          {pending && (
            <Button
              variant="outline"
              onClick={() => {
                setPending(false);
                setComplete(true);
                setOpen(false);
              }}
            >
              Complete request
            </Button>
          )}
        </AlertDialogContent>
      </AlertDialog>
      <p role="status" className="text-sm text-muted-foreground">
        {complete ? "Draft deleted locally" : "Draft retained"}
      </p>
    </div>
  );
}
```

## When to use

- A destructive or irreversible action — deleting a project, revoking a key, overwriting a draft — that the
  user must confirm on purpose.
- A decision the page cannot make for the user: move the workspace, leave without saving, end the session.
- A step that must be acknowledged before anything else continues, where an accidental dismissal would be
  the bug.

## When not to use

- A task with more than one decision or a form to fill in. Use `dialog`: it can be dismissed, and it should be.
- A message that does not block anything. Use `alert` where it belongs on the page, or `toast` for a moment.
- A hint attached to a control. Use `tooltip`.

## API

| Part | Props | Notes |
| --- | --- | --- |
| `AlertDialog` | `open`, `defaultOpen`, `onOpenChange`, `onOpenChangeComplete` | Base UI root. Always modal; pointer dismissal is fixed off. |
| `AlertDialogTrigger` | native button props, `render` | Opens the dialog. |
| `AlertDialogContent` | `size` (`"default" \| "sm"`), `render`, `className` | Renders portal, overlay, and popup. |
| `AlertDialogOverlay` | `className` | Only needed when replacing `AlertDialogContent`. |
| `AlertDialogHeader` / `AlertDialogFooter` | `className` | Layout only. |
| `AlertDialogMedia` | `className` | Icon slot; changes the header layout. |
| `AlertDialogTitle` | `className` | Required accessible name. |
| `AlertDialogDescription` | `className` | Supporting text; wire it to the decision, not the product. |
| `AlertDialogAction` | `variant`, `size`, `onClick`, `render` | Confirming Button. The caller owns closing via the root’s controlled `open` value. |
| `AlertDialogCancel` | `variant` (`outline`), `size`, `onClick`, `render` | Dismissing button. Also closes the dialog. |

`AlertDialogCancel` renders Base UI’s Close. `AlertDialogAction` matches the pinned upstream
Button: clicking it invokes the caller’s handler and leaves the popup open. Use controlled
`open` / `onOpenChange` to close when the caller decides the action is complete.

## Motion contract

Each portal surface resolves its own mode and token clock. A nested full scope restores timing inside none (subject to the system preference). Live reduced cancels scale or slide and keeps opacity; none cancels transitions and shows the first frame immediately. Base parts accept `className(state)` and `style(state)`; caller values merge last.

| Phase | Properties | Token | Interruptible |
| --- | --- | --- | --- |
| enter | overlay `opacity 0 → 1`; panel `opacity 0 → 1` + `scale 0.96 → 1` | `popup.anchored/css-transition` · `duration.fast` / `duration.base` | yes |
| exit | overlay `opacity → 0`; panel `opacity → 0` + `scale → 0.96` | `exit.fade/css-transition` · `duration.fast` / `duration.base` | yes (reopen mid-exit) |
| reduced | opacity only, no scale; the duration tokens run at 0.6× (overlay 96ms, panel 132ms) | `exit.fade/css-transition` | yes |
| none | every `--motion-duration-*` resolves to `0ms`, so no transition runs | – | – |

The entrance is the dialog's, because this is the same popup: a fade under a 0.96-scale settle. The
motion is CSS-only — Base UI toggles `data-starting-style` / `data-ending-style` and the class list
reads the duration tokens — so there is no JavaScript animation loop and nothing to interrupt by hand.
Reopening during the exit reverses the fade rather than restarting it.

## Keyboard interactions

| Keys | Action |
| --- | --- |
| Tab / Shift+Tab | Cycles focus inside the dialog. Focus never reaches the page behind it. |
| Escape | Cancels: the dialog closes and focus returns to the trigger. |
| Enter / Space | Activates the focused button — confirm or cancel, whichever has focus. |

The outside press is the one path that is deliberately missing: clicking the overlay does nothing,
which is the difference between this component and `dialog`.

## Accessibility

The destructive action uses foreground text on a tinted destructive background. This preserves the warning colour while meeting text contrast in both themes.

- Base UI provides `role="alertdialog"`, `aria-modal`, `aria-labelledby`, `aria-describedby`, focus
  trapping, focus return, scroll lock, and the Escape path.
- `AlertDialogTitle` is required: an alert dialog without an accessible name is invalid, and it is
  announced as the first thing inside the popup. `AlertDialogDescription` becomes the description, so
  put the consequence there, not in a second paragraph.
- Focus lands on the cancel control, the first tabbable element inside the popup, not on the destructive
  action — so a stray Enter cancels rather than confirms. Put `AlertDialogCancel` first in the footer for
  that reason; the footer's column-reverse layout still shows the confirming action on top.
- Destructive styling is colour plus a specific verb ("Delete project", not "OK"). Never rely on the
  red alone; the label has to carry the meaning in greyscale and in a screen reader.
- `AlertDialogMedia` is decorative when the title already says what happened. Mark the icon
  `aria-hidden="true"` unless it is the only signal.

## Responsive behavior

The panel is centred with a 1rem gutter on narrow viewports: `max-w-lg` for the default size and
`max-w-xs` for `size="sm"`. The footer stacks its buttons in reverse DOM order (the confirming action
on top) below `sm`, and becomes a row that ends on the right above it. With `size="sm"` the two
buttons split the width instead of stacking, so the two answers stay side by side at every size.

## Performance

- One popup tree is mounted only while open; the overlay and panel unmount after the exit transition.
- Animates `opacity` and `scale` only: no layout reads, no `width`/`height` transition, and no
  JavaScript animation running while the dialog sits open.
- `AlertDialogAction` and `AlertDialogCancel` are ordinary `Button`s, so the press feedback is the
  button's (a 0.97 scale that the same motion mode can drop).

## Notes for AI

- Reach for `alert-dialog` only when the answer must be deliberate. A form, a longer task, or anything
  the user may want to dismiss belongs in `dialog`.
- Always render `AlertDialogTitle`; it is the accessible name. Use `AlertDialogDescription` for the
  consequence of the action, in one sentence.
- Name the confirming button after its effect ("Delete project", "Leave without saving"), never "OK".
- Cancel closes automatically. The confirming Action stays open; use the root’s controlled `open` value when the caller decides to close.
- Use `AlertDialogMedia` for an icon, not for an illustration: the slot is a 4rem square that changes
  the header layout.
