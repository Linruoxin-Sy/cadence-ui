## Installation

**Command**

```install
npx shadcn@latest add @cadence/slider
```

**Manual**

[Manual installation files](https://cadence.dev/r/slider.json)

Copy every file in Slider's target list, keeping `slider/index.tsx` beside the
shared `lib/` directory, the relative imports intact and the sources'
`"use client"` directives. The thumb layer imports `ControlSpan` from
`control-animation.tsx`; that module also reaches `native-div.tsx` and
`press-button.tsx`. The root entrance is the shared `inline-entrance.ts`, and the
scoped paint owners come from `css-motion.ts`. Copy every file in the provider,
motion and utilities payloads, even when you do not wrap the application in a
provider. The provider files and `motion` package remain required imports.

Complete the base theme setup linked above and ensure Tailwind scans the copied
files. Slider needs no additional item-specific CSS, icon package or external
asset. A later-inserted slider fades in once on its root; the decorative thumb
face owns the press scale in full, while reduced and none keep that scale at one
with a zero clock. Pointer and keyboard values still update immediately in every
mode, and the fill is never animated: it follows Base UI's accepted geometry.
The track, the range, the thumb ring and the thumb face each own one scoped
colour clock, and real DOM focus settles that owner's paint immediately.
Standalone sliders follow the system motion preference. The optional
`CadenceProvider` controls a subtree's mode and timing; nested full still
respects system reduced motion.

Usage, the top specimen, Range, Vertical, Disabled, Thumb collisions, Thumb
alignment and Explicit motion scopes use only Slider and its included helpers.
Controlled also needs [Button](/components/button):

```install
npx shadcn@latest add @cadence/button
```

For manual installation, follow Button's Manual tab too and add
`button/index.tsx`. Its shared files are already in Slider's target list; the
additional npm dependency is:

```package-manager
npm install class-variance-authority
```

No example needs another package or external asset. The site's preview shell is
not consumer setup.

In Next.js App Router, Usage, Controlled and Range need a client module for
their `useState` and value-change handlers; Controlled also handles an external
button click. Vertical, Disabled, Thumb collisions, Thumb alignment and Explicit
motion scopes can be composed in a synchronous Server Component with the shown
JSX and serializable props; their existing client directives may also be kept.
An event handler, a function-valued `render`, `className(state)` or `style(state)`,
or a client-side hook such as `useState` or `useRef` needs a caller client
boundary. Keep the installed sources' client directives in either case.

Supply an explicit numeric `defaultValue` for an uncontrolled single thumb, or
own `value` with `onValueChange` for a controlled slider. Arrays create one thumb
per entry; use ordered values within `min` and `max`, a positive `step` and a
valid `minStepsBetweenValues` for the available range. `onValueChange` reports
user changes; `onValueCommitted` reports a completed change. An external state
reset does not create a user commit. `format` and `locale` change the announced
value text, not the stored number.

Give each slider an `aria-label` or `aria-labelledby`, and show the current
value when precision matters. With two thumbs, `aria-label` gains minimum and
maximum suffixes; larger arrays gain numbered suffixes. A supplied
`aria-labelledby` is shared by the thumbs, so choose labels that make the range
understandable. Each thumb contains a native `input[type="range"]`; the root
`id` is not that input's id. Root `aria-invalid` and `aria-describedby` are not
automatically copied onto each native input. The caller owns error text and
native thumb associations; this wrapper exposes no per-thumb props.

Tab visits enabled thumbs. In left-to-right direction, Right/Up increase and
Left/Down decrease by `step`; Page Up/Down and Shift+arrows use `largeStep`.
Home/End move to the permitted endpoint, respecting neighbouring thumbs and
their minimum separation. `thumbCollisionBehavior` selects the pointer policy;
it does not remove keyboard bounds. Horizontal sliders fill their container;
give a vertical slider an explicit height, as Vertical does. Cadence defaults to
edge alignment. `edge-client-only` keeps its thumbs hidden until client
measurement, so use edge or center when thumbs must be visible before hydration.

For native submission, supply `name` and optionally `form`. Each enabled thumb's
range input contributes a numeric string under the same name; use
`FormData.getAll(name)` for a range. There is no extra hidden aggregate input.
Disabled sliders ignore interaction, leave the tab sequence and contribute no
entries. The caller owns acceptable values, parsing, error messages, submission,
server-side validation and persistence. Keep these rules outside the UI; native
range bounds are not business validation.

## Usage

```tsx
"use client";

import { useState } from "react";
import { Slider } from "@/components/cadence/slider";

export function VolumeSlider() {
  const [volume, setVolume] = useState(68);
  return (
    <div className="grid w-full max-w-72 gap-3">
      <p className="flex items-center justify-between gap-4 text-sm">
        <span>Volume</span>
        <span className="text-muted-foreground tabular-nums">{volume}%</span>
      </p>
      <Slider aria-label="Volume" value={volume} onValueChange={setVolume} />
    </div>
  );
}
```

`defaultValue` and `value` accept a number for one thumb, or an array with one entry per thumb. `aria-label`
on the slider is forwarded to every thumb's native range input, which is what a
screen reader announces. A range slider gets one accessible name per thumb —
`Price (minimum)` and `Price (maximum)` — because two inputs with the same name
are indistinguishable.

## Controlled

The caller owns the numeric value. `onValueChange` updates it during a gesture; `onValueCommitted` records the completed user change. Reset volume is an external value update, so it does not invent a new user commit or change any other example.

<ComponentExample name="controlled" />

```tsx
"use client";

import { useState } from "react";
import { Button } from "@/components/cadence/button";
import { Slider } from "@/components/cadence/slider";

export function ControlledSlider() {
  const [volume, setVolume] = useState(60);
  const [committed, setCommitted] = useState<number | null>(null);
  return (
    <div className="grid w-full max-w-72 gap-4">
      <Slider value={volume} onValueChange={setVolume} onValueCommitted={setCommitted} aria-label="Controlled volume" />
      <p role="status" className="text-sm text-muted-foreground tabular-nums">
        Volume: {volume}%; last committed: {committed === null ? "not changed" : `${committed}%`}
      </p>
      <Button variant="outline" size="sm" onClick={() => setVolume(60)}>
        Reset volume
      </Button>
    </div>
  );
}
```

## Range

An array creates one thumb per entry. This price band steps by 10 and keeps two steps between values. Each thumb gets a distinct accessible name; `format` and `locale` provide currency value text without changing the stored numbers.

<ComponentExample name="range" />

```tsx
"use client";

import { useState } from "react";
import { Slider } from "@/components/cadence/slider";

export function PriceRange() {
  const [price, setPrice] = useState([120, 480]);
  return (
    <div className="grid w-full max-w-72 gap-3">
      <p className="text-sm tabular-nums">
        Price: ${price[0]} – ${price[1]}
      </p>
      <Slider
        value={price}
        onValueChange={setPrice}
        min={0}
        max={600}
        step={10}
        minStepsBetweenValues={2}
        format={{ style: "currency", currency: "USD", maximumFractionDigits: 0 }}
        locale="en-US"
        aria-label="Price"
      />
    </div>
  );
}
```

## Vertical

Give a vertical slider a height. This independent slider starts at 64 and uses the same native keyboard steps as the horizontal control; its track fills the supplied 10rem height.

<ComponentExample name="vertical" />

```tsx
"use client";

import { Slider } from "@/components/cadence/slider";

export function VerticalSlider() {
  return <Slider orientation="vertical" defaultValue={64} className="h-40" aria-label="Level" />;
}
```

## Disabled

The disabled slider stays visible at 40, but ignores pointer and keyboard changes. Explain the unavailable setting in nearby text rather than relying on a dimmed track alone.

<ComponentExample name="disabled" />

```tsx
"use client";

export function DisabledSlider() {
  return (
    <div className="grid w-full max-w-72 gap-3">
      <p className="text-sm text-muted-foreground">Volume unavailable: 40%</p>
      <Slider defaultValue={40} disabled aria-label="Unavailable volume" />
    </div>
  );
}
```

## Thumb collisions

Each range has a fixed collision policy. While dragging, `push` moves the neighbouring thumb, `swap` hands the active thumb across the other value, and `none` clamps at the other thumb. These are independent ranges with the same starting values, not a policy selector. Keyboard bounds still respect the ordered values.

<ComponentExample name="collisions" />

```tsx
"use client";

import { Slider } from "@/components/cadence/slider";

export function SliderCollisions() {
  return (
    <div className="grid w-full max-w-72 gap-6">
      {(["push", "swap", "none"] as const).map((behavior) => (
        <div key={behavior} className="grid gap-3">
          <p className="text-sm">{behavior === "none" ? "Clamped" : behavior === "push" ? "Push" : "Swap"}</p>
          <Slider defaultValue={[30, 60]} thumbCollisionBehavior={behavior} aria-label={`${behavior} range`} />
        </div>
      ))}
    </div>
  );
}
```

## Thumb alignment

Cadence defaults to `edge`, placing the whole thumb inside the track endpoints. `center` places its centre on the endpoint. `edge-client-only` retains its thumb and native input in the server DOM, hidden until client measurement reveals them with edge geometry. Without JavaScript they stay hidden; the track and this explanation remain readable. Use `edge` or `center` when thumbs must be visible before hydration.

<ComponentExample name="alignment" />

```tsx
"use client";

import { Slider } from "@/components/cadence/slider";

export function SliderAlignment() {
  return (
    <div className="grid w-full max-w-72 gap-6">
      {(["edge", "center", "edge-client-only"] as const).map((alignment) => (
        <div key={alignment} className="grid gap-3">
          <p className="text-sm">{alignment}</p>
          <Slider defaultValue={0} thumbAlignment={alignment} aria-label={`${alignment} alignment`} />
        </div>
      ))}
    </div>
  );
}
```

## Explicit motion scopes

The first slider is explicitly `none` from its first render. Its value still follows pointer and keyboard input immediately, with no press scale. The second explicitly restores `full` inside that scope, subject to the system reduced-motion preference. Ordinary examples inherit the site header.

<ComponentExample name="without-motion" />

```tsx
"use client";

import { CadenceProvider } from "@/components/cadence/lib/provider";
import { Slider } from "@/components/cadence/slider";

export function StaticSlider() {
  return (
    <CadenceProvider mode="none">
      <div className="grid w-full max-w-72 gap-6">
        <div data-testid="initial-none">
          <Slider defaultValue={50} aria-label="Static slider" />
        </div>
        <CadenceProvider mode="full">
          <Slider defaultValue={50} aria-label="Explicit full slider" />
        </CadenceProvider>
      </div>
    </CadenceProvider>
  );
}
```

## When to use

- A value where the rough position matters more than the exact number: volume,
  brightness, zoom, opacity.
- A range (two thumbs): price between, time window, budget band.
- A filter where the user should feel the bounds instead of typing them.

## When not to use

- An exact number matters and the range is wide; pair a `slider` with an `input`,
  or use `input` alone.
- Fewer than about five discrete options; use `radio-group` or `toggle-group`.
- A value with no natural order, like picking a colour name.

## API

| Prop                 | Type                              | Default        | Description                                     |
| -------------------- | --------------------------------- | -------------- | ----------------------------------------------- |
| `value`              | `number \| readonly number[]`     | –              | Controlled value, one entry per thumb.          |
| `defaultValue`       | same as `value`                   | –              | Uncontrolled initial value.                     |
| `onValueChange`      | `(value, details) => void`        | –              | Fired while dragging and on keyboard steps.     |
| `min`, `max`         | `number`                          | `0`, `100`     | Bounds.                                         |
| `step`               | `number`                          | `1`            | Snap increment.                                 |
| `orientation`        | `"horizontal" \| "vertical"`      | `"horizontal"` | Axis.                                           |
| `disabled`           | `boolean`                         | `false`        | Ignores pointer and keyboard.                   |
| `aria-label`         | `string`                          | –              | Forwarded to each thumb, suffixed per thumb.    |
| `className`          | `string` / state callback                          | –              | Merged last.                                    |

Base UI's `format`, `locale`, and `minStepsBetweenValues` are forwarded unchanged.

| Additional prop | Type | Default | Description |
| --- | --- | --- | --- |
| `onValueCommitted` | `(value, details) => void` | – | Reports a completed user change. |
| `largeStep` | `number` | `10` | Page and Shift+arrow increment. |
| `minStepsBetweenValues` | `number` | `0` | Minimum separation, in steps. |
| `thumbCollisionBehavior` | `"push" \| "swap" \| "none"` | `"push"` | Pointer collision policy. |
| `thumbAlignment` | `"edge" \| "center" \| "edge-client-only"` | `"edge"` | Thumb position at endpoints. |
| `name`, `form` | `string` | – | Native form identity and owner. |

## Motion contract

Authored intensity is **subtle**: The native thumb stays on Base UI input geometry, a decorative face owns the press scale, and each track, range and thumb part owns one scoped palette; value input and a readout stay immediate.

The thumb is the protagonist: a decorative face compresses while the thumb is dragged and
springs back on release, the same press language as `button` and `toggle`. The native
positional layer keeps the coordinate box, the hit target and the focus ring, so the press
never moves what the pointer is aiming at or clips the ring.

| Recipe / form | Owner and full behaviour | reduced | none |
| ------------- | ------------------------ | ------- | ---- |
| `data.transition/one-shot` | One opacity entrance on a slider inserted into an already-presented page, with already-correct value geometry. A presenting parent, a hidden host and an already-visible control keep native paint. | Short opacity. | Immediate. |
| `feedback.press/one-shot` | The decorative thumb face scales to 0.97 while the drag is accepted and springs back on release; the native thumb never moves. | No scale; the ring and the fill carry the interaction. | No tween. |
| `state.color/css-transition` | The track, the range, the thumb ring and the thumb face each own one scoped paint set on one clock. Real DOM focus settles that owner's declared paint at its target, and a palette we cannot prove does the same. | Short eligible colour. | Zero duration and delay. |

Value input is never animated: the fill and the thumb follow Base UI's accepted geometry
immediately, so a transition would make the fill trail the pointer by one frame per move.
The range extent, thumb placement and indicator measurement therefore stay with the
primitive in every mode. A programmatic value is also placed immediately: there is no
verified single-owner adapter for an authored retarget, so Slider does not claim a second
position writer. A composed numeric readout belongs to its own display owner; it may roll
on a discrete committed change and must stay immediate during direct manipulation.

Live reduction removes the press scale and settles the entrance and colour clocks, while
the accepted value, native capture and an active pointer or keyboard operation keep their
current position. `none` and a zero clock cancel every writer and delay. A native form reset
stays Base UI's own path: Cadence adds no callback, revision or replay for it.

## Keyboard interactions

| Keys                | Action                                  |
| ------------------- | --------------------------------------- |
| `Tab`               | Moves focus to the thumb.               |
| `Arrow Right/Up`    | Increases by one `step`.                |
| `Arrow Left/Down`   | Decreases by one `step`.                |
| `Page Up`/`Page Down` | Moves by a larger increment.           |
| `Home`/`End`        | Jumps to `min` / `max`.                 |

## Accessibility

- Every thumb contains a native `input[type=range]`, so the control works with
  assistive technology without a custom role.
- Always pass `aria-label` (or `aria-labelledby`) — the fill has no text.
- Show the current value as text next to the slider when the number matters.
  Dragging is not a way to read a value.
- Supplied `aria-invalid` stays on the root; this wrapper does not add destructive colours or per-thumb error descriptions. The caller owns error text and native thumb associations (P11).

## Validation and data ownership

| The component does                                | You do                                              |
| ------------------------------------------------- | --------------------------------------------------- |
| Reports the value through `onValueChange`         | Deciding whether the range is acceptable            |
| Forwards supplied `aria-invalid` on the root                             | Writing the error text and its `aria-describedby` id |
| Steps and clamps the value to `min`/`max`         | Server-side bounds and business rules               |

[Field](/components/field) shows how the invalid state and its message are wired.

## Responsive behavior

Horizontal sliders fill their container (`w-full`); vertical ones fill their
height. On touch screens the thumb keeps a 16px visual size but the range input
covers the whole control, so drag targets stay reachable.

## Performance

The value updates on pointer move without React re-rendering the whole form: Base
UI moves the thumb and the range with its own layout, and one Motion element per
thumb face animates only the press scale. The scoped colour families are CSS
transitions on short-lived state changes, with no `layout` animation, no
measurement per frame and no observer or roller per pointer event.

## Notes for AI

- A numeric value renders one thumb; an array renders one thumb per entry. Omitting both values retains the upstream two-thumb default.
- Do not animate the fill or the thumb's position. Motion here is press scale, one root entrance and scoped colour only.
- Pair with an `input` when the exact number must be typeable.
