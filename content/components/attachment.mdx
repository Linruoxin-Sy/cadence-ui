## Installation

**Command**

```install
npx shadcn@latest add @cadence/attachment
```

The examples use lucide-react icons; run `pnpm add lucide-react` if needed. The file-selection example also installs Input; Button and the provider are Attachment dependencies.

```install
npx shadcn@latest add @cadence/input
```

**Manual**

[Manual installation files](https://cadence.dev/r/attachment.json)

Copy all 10 target files, including every shared motion and provider helper.
Keep the sibling `cadence/` tree, relative imports and shipped `"use client"`
directives. Complete the linked manual base setup with Cadence theme CSS,
ensure Tailwind CSS v4 scans the copied files, and apply
`bg-background text-foreground` to your application root. No additional
item-specific stylesheet or upload runtime is required. The provider files
are required imports; wrapping the application is optional. Standalone parts
follow the system motion preference; a provider selects a local mode or
recipe clock.

The icons in Usage and the examples additionally require:

```package-manager
npm install lucide-react
```

For Caller-owned file selection, also copy Input's complete source below.
Its direct registry dependency is `@cadence/cadence-utils`; reuse the
`lib/cn.ts` file already copied above. Its full recursive npm dependencies
are `@base-ui/react`, `clsx` and `tailwind-merge`, already included in the
base command. No additional CSS is needed. The [Input Manual](/components/input#installation)
also exposes its complete source block.

| Additional item | Target file | Full source |
| --- | --- | --- |
| [@cadence/input](https://cadence.dev/r/input.json) | `@components/cadence/input/index.tsx` | [JSON files[].content](https://cadence.dev/r/input.json) |

Button and CadenceProvider imports in the examples are covered by the base
graph. Keep hooks, local state, event handlers, refs, render functions and
Button callback classes/styles in a `"use client"` caller. Usage removes a
card and restores focus through client state and a ref. File selection reads
the browser's FileList and File metadata inside its change handler. Static
metadata, serializable state/size/orientation props and a native anchor JSX
element with `href`/`download` can be composed in a Server Component; they
do not require caller hooks. The installed parts retain their client boundary.

Attachment displays `state`; it stores no File or request state. The caller
owns selection, upload requests, progress, processing, failure/retry, cancellation,
removal and persistence. The file-selection example simulates milestones without
requests and clears its native input on reset/removal. Supply download and
preview URLs yourself, including permissions and lifetime. If creating object
URLs, revoke superseded URLs and clean them up on unmount after their consumers
finish using them; Attachment creates or revokes none. The inline data URLs in
these examples have no object URL cleanup. Render application errors through
`aria-invalid`, descriptive text and `aria-describedby`; announce milestones
outside a busy region. The component supplies no validation or hidden form value.

Keep the overlay trigger and actions as siblings. Name icon-only controls,
preserve image alt text, and choose a focus destination when removing a focused
card. The default trigger is a native `type="button"`; a rendered anchor owns
its native link/download behavior. Custom render functions must spread the
supplied props and retain the ref on a focusable element. Retain Button's
native/disabled semantics when customizing actions. Keep parents shrinkable:
filenames truncate, and AttachmentGroup scrolls horizontally with native
snap points. The group does not own card orientation or list virtualization.

Uploading and processing titles use the theme's `animate-pulse` opacity loop
in full and reduced modes; none applies `animate-none` and leaves text opaque.
The provider's `timeScale` controls recipes, not this continuous CSS clock;
retune `--animate-pulse` in the theme when needed. Default actions use Button's
`feedback.press` scale in full, with no scale in reduced/none. State, file,
size, orientation, media and removal updates are immediate in every mode;
Attachment adds no entry, exit or measured resize animation.

## Usage

This ready file has a native download link and an independent remove action. The caller chooses the removal focus destination.

```tsx
"use client";

import { FileTextIcon, XIcon } from "lucide-react";
import { useRef, useState } from "react";
import { Attachment, AttachmentAction, AttachmentActions, AttachmentContent, AttachmentDescription, AttachmentMedia, AttachmentTitle, AttachmentTrigger } from "@/components/cadence/attachment";

const noteUrl = "data:text/plain;charset=utf-8,Project%20notes%0AReview%20the%20attachment%20examples.";

export function ReadyFile() {
  const [removed, setRemoved] = useState(false);
  const region = useRef<HTMLDivElement>(null);
  return (
    <div ref={region} tabIndex={-1} className="max-w-full outline-none focus-visible:ring-2 focus-visible:ring-ring">
      {removed ? (
        <p className="text-sm text-muted-foreground">No attached files.</p>
      ) : (
        <Attachment>
          <AttachmentMedia aria-hidden="true">
            <FileTextIcon />
          </AttachmentMedia>
          <AttachmentContent>
            <AttachmentTitle>project-notes.txt</AttachmentTitle>
            <AttachmentDescription>Text file · 45 B</AttachmentDescription>
          </AttachmentContent>
          <AttachmentTrigger
            render={<a href={noteUrl} download="project-notes.txt" aria-label="Download project notes" />}
          />
          <AttachmentActions>
            <AttachmentAction
              aria-label="Remove project notes"
              onClick={() => {
                setRemoved(true);
                region.current?.focus();
              }}
            >
              <XIcon />
            </AttachmentAction>
          </AttachmentActions>
        </Attachment>
      )}
    </div>
  );
}
```

## Upload state

Pass all five caller-owned states directly: idle, uploading, processing, error and done. Uploading and processing pulse the filename; readable status remains when motion is disabled. These fixed cards do not upload anything. A busy region uses aria-busy; announce meaningful milestones in a separate polite status, rather than each percentage.

<ComponentExample name="upload-state" />

```tsx
import { FileTextIcon } from "lucide-react";
import { type ComponentProps } from "react";
import { Attachment, AttachmentContent, AttachmentDescription, AttachmentMedia, AttachmentTitle } from "@/components/cadence/attachment";

function FileTile({
  name = "project-notes.txt",
  description = "Text file · 45 B",
  ...props
}: ComponentProps<typeof Attachment> & { name?: string; description?: string }) {
  return (
    <Attachment {...props}>
      <AttachmentMedia aria-hidden="true">
        <FileTextIcon />
      </AttachmentMedia>
      <AttachmentContent>
        <AttachmentTitle title={name}>{name}</AttachmentTitle>
        <AttachmentDescription>{description}</AttachmentDescription>
      </AttachmentContent>
    </Attachment>
  );
}

export function UploadState() {
  const states = ["idle", "uploading", "processing", "error", "done"] as const;
  const descriptions = {
    idle: "Ready to upload",
    uploading: "Uploading · 64%",
    processing: "Processing file",
    error: "Upload failed · connection lost",
    done: "Upload complete",
  };
  return (
    <div className="flex w-full min-w-0 flex-wrap justify-center gap-3">
      {states.map((state) => (
        <FileTile
          key={state}
          state={state}
          name={`${state}.pdf`}
          description={descriptions[state]}
          aria-busy={state === "uploading" || state === "processing"}
        />
      ))}
    </div>
  );
}
```

## Images

Supply the URL yourself; Attachment never creates or revokes object URLs. This static inline SVG has no object URL lifecycle. Horizontal cards remain the default, as shown in Sizes.

## Trigger and independent actions

AttachmentTrigger fills the card behind AttachmentActions. The native download link has an accessible name; Save toggles its own state without requesting a download. The disabled delete button stays disabled. This local text download uses a fixed data URL; an application supplies its own file URL and authorization. Default triggers are non-submitting buttons, and actions default to ghost Button with icon-xs size.

<ComponentExample name="trigger-and-actions" />

```tsx
"use client";

import { XIcon } from "lucide-react";
import { useState } from "react";
import { Attachment, AttachmentAction, AttachmentActions, AttachmentContent, AttachmentDescription, AttachmentTitle, AttachmentTrigger } from "@/components/cadence/attachment";

const noteUrl = "data:text/plain;charset=utf-8,Project%20notes%0AReview%20the%20attachment%20examples.";

export function TriggerAndActions() {
  const [opened, setOpened] = useState(0);
  const [saved, setSaved] = useState(false);
  return (
    <div className="flex min-w-0 max-w-full flex-col items-start gap-3">
      <Attachment>
        <AttachmentContent>
          <AttachmentTitle>review-notes.txt</AttachmentTitle>
          <AttachmentDescription>Download or save independently</AttachmentDescription>
        </AttachmentContent>
        <AttachmentTrigger
          aria-label="Download review notes"
          onClick={() => setOpened((n) => n + 1)}
          render={<a href={noteUrl} download="review-notes.txt" />}
        />
        <AttachmentActions>
          <AttachmentAction size="sm" onClick={() => setSaved((v) => !v)} aria-pressed={saved}>
            {saved ? "Saved" : "Save"}
          </AttachmentAction>
          <AttachmentAction aria-label="Delete locked review notes" disabled>
            <XIcon />
          </AttachmentAction>
        </AttachmentActions>
      </Attachment>
      <output className="text-sm text-muted-foreground">
        Downloads requested: {opened}; {saved ? "saved" : "not saved"}.
      </output>
    </div>
  );
}
```

## Caller-owned file selection

The native Input owns its FileList, name and browser file selection. This example stores a File locally and exposes explicit simulation actions for progress, processing, completion, failure and retry; it never starts a request or validates the file. Inspect reads the selected metadata. Selection, reset and removal remain independent of the other examples. Reset clears the native input, and removal returns focus to that same input. A real application owns requests, errors, cancellation and cleanup.

<ComponentExample name="caller-owned-file-selection" />

```tsx
"use client";

import { FileTextIcon, XIcon } from "lucide-react";
import { type ComponentProps, useId, useRef, useState } from "react";
import { Attachment, AttachmentAction, AttachmentActions, AttachmentContent, AttachmentDescription, AttachmentMedia, AttachmentTitle, AttachmentTrigger } from "@/components/cadence/attachment";
import { Button } from "@/components/cadence/button";
import { Input } from "@/components/cadence/input";

export function CallerOwnedFileSelection() {
  const id = useId();
  const input = useRef<HTMLInputElement>(null);
  const form = useRef<HTMLFormElement>(null);
  const [file, setFile] = useState<File | null>(null);
  const [state, setState] = useState<NonNullable<ComponentProps<typeof Attachment>["state"]>>("idle");
  const [notice, setNotice] = useState("No file selected. This example makes no requests.");
  const descriptions = {
    idle: "Selected locally · no upload started",
    uploading: "Local simulation · 64%",
    processing: "Local simulation · processing",
    error: "Caller supplied: connection lost",
    done: "Local simulation complete",
  };
  function update(next: typeof state) {
    setState(next);
    setNotice(descriptions[next]);
  }
  return (
    <form
      ref={form}
      onSubmit={(event) => event.preventDefault()}
      className="flex w-full min-w-0 max-w-lg flex-col items-start gap-3"
    >
      <label htmlFor={`${id}-file`} className="text-sm font-medium">
        Choose a local file (name only)
      </label>
      <Input
        ref={input}
        id={`${id}-file`}
        name="attachment"
        type="file"
        aria-describedby={`${id}-notice`}
        onChange={(event) => {
          const selected = event.target.files?.[0] ?? null;
          setFile(selected);
          setState("idle");
          setNotice(selected ? `Selected ${selected.name}; no request started.` : "No file selected.");
        }}
      />
      {file && (
        <Attachment
          state={state}
          aria-busy={state === "uploading" || state === "processing"}
          aria-invalid={state === "error" || undefined}
          aria-describedby={state === "error" ? `${id}-error` : undefined}
        >
          <AttachmentMedia aria-hidden="true">
            <FileTextIcon />
          </AttachmentMedia>
          <AttachmentContent>
            <AttachmentTitle title={file.name}>{file.name}</AttachmentTitle>
            <AttachmentDescription>{descriptions[state]}</AttachmentDescription>
          </AttachmentContent>
          <AttachmentTrigger
            aria-label={`Inspect ${file.name}`}
            onClick={() => setNotice(`${file.name} · ${file.size} bytes · ${file.type || "unknown type"}`)}
          />
          <AttachmentActions>
            <AttachmentAction
              aria-label={`Remove ${file.name}`}
              onClick={() => {
                setFile(null);
                setState("idle");
                form.current?.reset();
                setNotice(`Removed ${file.name}`);
                input.current?.focus();
              }}
            >
              <XIcon />
            </AttachmentAction>
          </AttachmentActions>
        </Attachment>
      )}
      {state === "error" && file && (
        <p id={`${id}-error`} className="text-sm text-destructive">
          Connection lost. Retry when your application is ready.
        </p>
      )}
      <div className="flex max-w-full flex-wrap gap-2">
        <Button type="button" variant="outline" size="sm" disabled={!file} onClick={() => update("uploading")}>
          Start local simulation
        </Button>
        <Button
          type="button"
          variant="outline"
          size="sm"
          disabled={!file || state !== "uploading"}
          onClick={() => update("processing")}
        >
          Process locally
        </Button>
        <Button
          type="button"
          variant="outline"
          size="sm"
          disabled={!file || state !== "processing"}
          onClick={() => update("done")}
        >
          Finish locally
        </Button>
        <Button type="button" variant="outline" size="sm" disabled={!file} onClick={() => update("error")}>
          Supply failure
        </Button>
        <Button
          type="button"
          variant="outline"
          size="sm"
          disabled={!file || state !== "error"}
          onClick={() => update("uploading")}
        >
          Retry locally
        </Button>
        <Button
          type="button"
          variant="outline"
          size="sm"
          onClick={() => {
            form.current?.reset();
            setFile(null);
            setState("idle");
            setNotice("Local selection reset.");
            input.current?.focus();
          }}
        >
          Reset selection
        </Button>
      </div>
      <p id={`${id}-notice`} role="status" className="max-w-full break-all text-sm text-muted-foreground">
        {notice}
      </p>
    </form>
  );
}
```

## Custom parts

Native root classes, styles and keyboard events pass through. Focus inspect uses a caller ref, and F2 inside the card focuses the same rendered button. The trigger uses Base UI render-function props; the independent download action demonstrates an anchor with Button callback classes and styles. Keep controls as siblings in the action layer rather than nesting them inside a trigger.

<ComponentExample name="custom-parts" />

```tsx
"use client";

import { useRef, useState } from "react";
import { Attachment, AttachmentAction, AttachmentActions, AttachmentContent, AttachmentDescription, AttachmentTitle, AttachmentTrigger } from "@/components/cadence/attachment";
import { Button } from "@/components/cadence/button";

const noteUrl = "data:text/plain;charset=utf-8,Project%20notes%0AReview%20the%20attachment%20examples.";

export function CustomParts() {
  const trigger = useRef<HTMLButtonElement>(null);
  const [count, setCount] = useState(0);
  return (
    <div className="flex min-w-0 max-w-full flex-col items-start gap-3">
      <Attachment
        className="rounded-none"
        style={{ borderStyle: "dashed" }}
        onKeyDown={(event) => {
          if (event.key === "F2") trigger.current?.focus();
        }}
      >
        <AttachmentContent>
          <AttachmentTitle>custom-notes.txt</AttachmentTitle>
          <AttachmentDescription>F2 focuses the inspect button</AttachmentDescription>
        </AttachmentContent>
        <AttachmentTrigger
          ref={trigger}
          aria-label="Inspect custom notes"
          onClick={() => setCount((n) => n + 1)}
          render={(props) => <button {...props} type="button" data-caller-trigger="yes" />}
        />
        <AttachmentActions>
          <AttachmentAction
            render={<a href={noteUrl} download="custom-notes.txt" />}
            size="sm"
            className={(s) => (s.disabled ? "opacity-50" : "underline")}
            style={(s) => ({ fontWeight: s.disabled ? 400 : 600 })}
          >
            Download
          </AttachmentAction>
        </AttachmentActions>
      </Attachment>
      <Button variant="outline" size="sm" onClick={() => trigger.current?.focus()}>
        Focus inspect
      </Button>
      <output className="text-sm text-muted-foreground">Inspections: {count}</output>
    </div>
  );
}
```

## When to use

File previews in composers, upload lists, or message attachments with caller-owned
metadata and optional open/remove/retry actions.

## When not to use

Use Input for native file selection, Progress for a standalone percentage, and
Item for generic content that does not represent a file. Attachment does not
implement an uploader, drop zone, file parser or streaming message runtime.

## API

| Part | Props and defaults |
| --- | --- |
| `Attachment` | Native div props; state `done`, size `default`, orientation `horizontal` |
| `AttachmentMedia` | Native div props; variant `icon` or `image`, default `icon` |
| `AttachmentContent` | Native div props; wraps metadata |
| `AttachmentTitle` | Native span props; filename, busy opacity loop |
| `AttachmentDescription` | Native span props; metadata/status text |
| `AttachmentActions` | Native div props; independent action layer |
| `AttachmentAction` | All Button props; size `icon-xs`, variant falls back to `ghost` |
| `AttachmentTrigger` | Base UI useRender button props; type `button` without render; render element/function |
| `AttachmentGroup` | Native div props; horizontal scroll and snap |

Every part preserves its upstream `attachment-*` data-slot (root: `attachment`).
Native refs, styles and events pass through; classes merge last. Root also exposes
`data-state`, `data-size`, `data-orientation`; media exposes `data-variant`.
No File or request state is stored internally. There is no default upload action.

## Motion contract

Authored intensity is **subtle**: Progress feedback stays within the attachment; it introduces no upload state or surface choreography.

| Cause | Recipe | Full | Reduced | None |
| --- | --- | --- | --- | --- |
| Uploading/processing title | `data.transition/continuous` | Opacity pulse via theme `animate-pulse` | Same opacity loop, no transform | `animate-none`, opacity 1 |
| Default action pressed | `feedback.press/one-shot` | Button token spring/press scale | No scale | Instant, no scale |

Continuous timing comes from the project's `--animate-pulse` theme token. This
replaces upstream's travelling shimmer with opacity to stay in the motion budget.
Root/title and default actions expose `data-motion`; live none cancels the loop
without replacing nodes. State, removal, size, orientation and media updates are
immediate. No entry, exit, layout or geometry recipe is implied. Custom render
controls can own their own feedback as with Button.

## Keyboard interactions

Tab reaches triggers and actions separately. Enter/Space activate default buttons;
a rendered link uses native link behaviour. Disabled actions retain Button's native
semantics. A focusable group scrolls with arrow keys; Tab also reveals off-screen
interactive cards. Removal focus policy belongs to the caller.

## Accessibility

Name every icon-only action and overlay trigger, retain meaningful image alt text,
and describe failures in text. The trigger has a visible focus ring. Avoid nested
interactive elements inside triggers. Provide a polite live region for upload
milestones outside a busy region. Truncated filenames remain in the DOM; a title
attribute or your own details view can expose their full visual text.

## Validation and data ownership

The application owns native file input `name`, `accept`, `multiple`, `required`,
File objects, form submission, validation, upload progress, requests, cancel/retry,
URLs and URL cleanup. Attachment forwards `aria-invalid`/`data-invalid` when given;
`state="error"` only styles a supplied failure. It never decides which file is valid.
The Caller-owned file selection example reports a local filename and simulates milestones without requests. Its fixed failure is supplied by the caller, not inferred from the selected File.

## Responsiveness and performance

Cards cap at their parent's width; long names truncate. Groups scroll horizontally
with no document overflow when their parent can shrink. Large lists should be
paginated or virtualized by the application. The busy opacity loop uses CSS with
no per-frame JavaScript or layout reads; none stops it on the next style update.
No @shadcn/react dependency or streaming runtime is needed for this pinned API.

## AI usage notes

Compose these nine parts; keep upload state and file lifecycle in your application.
Do not infer a network operation from the visual `state` value. Prefer stable file
IDs as keys so a progress update preserves focus and the native input. There is no
message streaming dependency and no reason to remount a composer when a file changes.
