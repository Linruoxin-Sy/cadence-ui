## Principles

1. **Motion explains cause and effect.** If you cannot say what changed and why, remove it.
2. **One protagonist at a time.** Do not move, scale, rotate, and recolor the same element at once.
3. **Duration follows hierarchy.** Small controls are fast, panels are medium, whole sections are slow.
4. **Interruptible by default.** A layout spring that is retargeted mid-flight keeps the velocity it
   already has.
5. **Reduced motion is equivalent.** Drop travel and scale, keep the state change readable.

## Tokens

Durations are seconds, easings are cubic-bezier tuples, springs use Motion's spring options.

| Token | Value | Used for |
| --- | --- | --- |
| `duration.instant` | 0.1 | Press, toggle |
| `duration.fast` | 0.16 | Small exits |
| `duration.base` | 0.22 | Default |
| `duration.slow` | 0.32 | Panels, drawers, text |
| `duration.page` | 0.45 | Full-page reveals |
| `ease.out` | `[0.22, 1, 0.36, 1]` | Entrances |
| `ease.inOut` | `[0.65, 0, 0.35, 1]` | Movement on screen |
| `ease.in` | `[0.7, 0, 0.84, 0]` | Exits |
| `spring.press` | visualDuration 0.24, bounce 0.12 | Press feedback |
| `spring.snappy` | visualDuration 0.26, bounce 0 | Popovers, small panels |
| `spring.travel` | visualDuration 0.3, bounce 0 | Value handoffs, travel between two anchors |
| `spring.smooth` | visualDuration 0.4, bounce 0 | Dialogs, layout |
| `spring.morph` | visualDuration 0.42, bounce 0 | Shared elements, width changes |
| `spring.sizeCompact` | visualDuration 0.28, bounce 0 | Internal compact-size parameter selection |
| `spring.sizePanel` | visualDuration 0.36, bounce 0 | Internal panel-size parameter selection |
| `rotation.halfTurn` | 180 degrees | Semantic disclosure orientation |

The size refinements and internal purpose-preset resolver select parameters only. Existing components
keep their documented recipe assignments; these values do not install a new geometry controller,
text diff, numeric reel or public animation primitive. CSS recipe tokens are generated from the
shared motion source; theme `--animate-*` loop clocks remain independently tunable.

Do not invent new values. If a component needs a different feel, add a recipe to `lib/motion.ts`
and document it.

Springs are authored as `visualDuration + bounce`. The two layout recipes (`layout.move`,
`layout.shared`) are restated as physical springs at runtime, after `timeScale`, so an interrupted
animation keeps its speed; the other springs stay time-defined because their travel is small enough
that inherited velocity would oscillate.

## Recipes

A recipe is a named transition. Components call `useCadenceMotion().transition("reveal")` instead of
writing durations inline.

| Recipe | Used by | Character |
| --- | --- | --- |
| `reveal` | sections, tab panels | 0.22s ease-out |
| `enter.pop` | popovers | snappy spring |
| `exit.fade` | backdrops, dismissed layers | 0.16s ease-in |
| `exit.shrink` | closing panels | 0.16s ease-in |
| `popup.anchored` | dialog panel | smooth spring |
| `layout.move` | reorder, list shifts | smooth spring, physics (velocity kept) |
| `layout.shared` | tab indicator | morph spring, physics (velocity kept) |
| `list.stagger` | staggered lists | 0.22s + stagger |
| `gesture.drag` | carousel, sheet | snappy spring |
| `scroll.progress` | scroll bar | smooth spring |
| `scroll.navigate` | Toc section links | 0.45s ease-in-out; immediate under reduced/none |
| `scroll.story` | scroll narratives (optional GSAP) | 0.32s |
| `text.reveal` | per-word reveals | 0.32s |
| `text.change` | [Animated Text](/components/animated-text) | Changed-only opacity; immediate exact native text when proof is unavailable |
| `text.split` | per-character reveals (optional GSAP) | 0.32s |
| `number.roll` | [Animated Number](/components/animated-number) | Bounded two-cell reels, smooth physics; reduced/none immediately settle |
| `data.transition` | skeletons, loading surfaces | opacity loop (CSS), 0.22s when one-shot |
| `state.morph` | checkbox, radio, switch, input-otp | morph spring |
| `state.color` | Scoped background, foreground, border and SVG colour feedback | Explicit CSS properties; reduced shortens timing; none cancels active duration/delay |
| `geometry.resize` | accordion, button width, select trigger | morph spring, physics, clamped |
| `handoff` | select value, toast origin | travel spring, physics |
| `feedback.press` | buttons | press spring |

## Scoped colour and status policy

The provider library includes shared CSS execution support for `state.color` and theme-clock
spin/pulse status. Components adopt it individually; each component's Motion contract remains the
source of its delivered behavior. [Animated Text](/components/animated-text) is installable for plain
strings. [Animated Number](/components/animated-number) is installable for independently committed
quantities, with raw defaults or explicit Intl formatting. [Reveal](/components/reveal) and
[Reveal Group](/components/reveal-group) provide explicit viewport entrances as described below.
Both display primitives retain exact native fallback when typography or layout correspondence is unproven.

A colour owner names its background, foreground, individual borders or SVG fill/stroke. Focus and
invalid indicators update immediately. Foreground/background animation requires a reviewed palette
with readable intermediate colours; the executor defaults to immediate paint without that proof.
Shadow feedback retains fixed geometry. A conflicting caller CSS transition/animation family keeps
its writer through mode/clock edits; removing the override restores shared ownership.

Migrated continuous owners use theme `--animate-*` clocks independently of provider timeScale.
They stop in reduced/none and while hidden/offscreen, then resume eligible full activity without
replaying missed work. Caller dimming remains static. Spinner and Skeleton still document their
legacy reduced behavior. Native intent delays, Toast lifetime, focus and direct input keep their timing.

## Reduced motion

A component never invents its own reduced variant. It asks the provider which mode is live and
renders accordingly:

- `full` — the recipe as authored.
- `reduced` — travel and scale dropped, tween durations ×0.6, opacity kept.
- `none` — every duration zero.

The mode comes from the OS `prefers-reduced-motion`, an enclosing `CadenceProvider`, or the
`data-motion` attribute for plain CSS. Components branch on `useCadenceMotion().reduced`, so a
reduced render never depends on a media query alone.

The resolution order, the component contract, and the three-mode test matrix live in
[Motion modes](/docs/motion-modes).

## Viewport entrances

Install [Reveal](/components/reveal) for one explicit native host, or
[Reveal Group](/components/reveal-group) for shared root/replay/trigger policy and optional bounded rhythm.
Both are independent registry items; the group installs Reveal as a namespaced dependency.

```install
npx shadcn@latest add @cadence/reveal-group
```

```tsx
import { Reveal } from "@/components/cadence/reveal";
import { RevealGroup } from "@/components/cadence/reveal-group";

export function Chapters() {
  return <RevealGroup stagger="cycle"><Reveal render={<section />}>Native content</Reveal></RevealGroup>;
}
```

Server HTML and first-screen hydration remain visible. Only successfully registered offscreen content
arms; reduced/none bypass hiding and observation. Default once/no-stagger and shared root-height
insets avoid replaying consumed content. Root/policy changes consume mounted entrances immediately.
Nested Reveal consumes only the same parent entrance; later independent child mounts remain eligible.
Use separate hosts for child press/layout/geometry. Existing ordinary components and the site's earlier
reveal path keep their own contracts; installing the primitive creates no implicit catalogue effect.

## Writing a component

```tsx
import { Reveal } from "@/components/cadence/reveal";

export function Example() {
  return <Reveal render={<section />}>Visible native content</Reveal>;
}
```

Five rules for new components:

1. Import presets from `../lib/motion`; never hard-code a duration.
2. Use explicit recipe properties: transform, opacity or bounded filter for visual motion,
   clamped `geometry.resize` for measured width/height, and `scroll.navigate` for section offsets.
   Shared `state.color` owns its declared colour/shadow properties, with verified readability or
   immediate fallback. Never use `transition: all`.
3. Give every animation an explicit reduced branch: applicable short opacity/colour feedback,
   immediate spatial targets and static migrated loops. None cancels owned duration and delay.
   Shared support does not certify an unmigrated component; standalone primitives have explicit installs.
4. Use `data-slot` on each part so consumers can target it with CSS.
5. Add a Motion contract table to the component's docs.

## Previewing motion

The three modes and the playback speed are switched **once, in the header**, and apply to the whole
site: they are settings, not properties of the page you happen to be reading. Both are remembered
(`localStorage`) and written into the URL, so `?motion=reduced&speed=0.25` can be shared with a
reviewer and still lands on exactly that state.

The speed gear is `timeScale` with the fraction inverted — `0.25×` is `timeScale={4}` — and it
covers the whole site rather than one preview, so a slow-motion pass shows a page's own entrances
and the components on it in the same tempo.

```
?motion=full | reduced | none      the site-wide mode
?speed=2 | 1 | 0.5 | 0.25          the site-wide playback speed
?motion=none                       a link the Playwright matrix navigates to
```

`none` is a forced downgrade, not a quieter `reduced`: every duration resolves to zero, so CSS popups
finish on the first frame exactly like Motion-driven ones.

If you want the slowdown inside your own app, it is a provider prop, not a token edit:

```tsx
<CadenceProvider timeScale={4}>…</CadenceProvider>  // 0.25×, same as the docs preview
```

`timeScale` multiplies durations, spring `visualDuration`, and delays, and re-derives the physical
springs after scaling. It never changes a token, and it cannot revive a transition under `none`.
Continuous CSS loops retain the theme's `--animate-pulse` / `--animate-spin` clock;
retune those theme tokens to change their speed. Provider `timeScale` does not multiply them.

A nested provider inherits whatever it does not set, which is how the preview slows down without
resetting the header's mode:

```tsx
<CadenceProvider timeScale={4}>…</CadenceProvider>        // keeps the enclosing mode
<CadenceProvider mode="full">…</CadenceProvider>          // deliberately opts back in
```

## Performance budget

| Metric | Budget |
| --- | --- |
| Initial Motion runtime | ≤ 48000 B gzip |
| Component addition | ≤ 8000 B gzip, declared shared runtime excluded |
| Complete-page initial JS | ≤ 120000 B gzip, including automatic async loads |
| Copied source | by tier: T0 4 KB, T1 6 KB, T2 10 KB, T3 12 KB, T4 14 KB gzip (`meta.tier`) |
| Layout stability | CLS < 0.02 |
| Presented frame rate | ≥ 55 fps on a real midrange mobile device |
| Concurrent animated elements | ≤ 20 |
| Total stagger | ≤ 400 ms |
| Animated properties | explicit recipe properties: visual transform/opacity/bounded filter, measured geometry and scoped colour; documented native engine/scroll exceptions |

Run `pnpm registry:check` before opening a pull request; it enforces the per-item size budget
and the reduced-motion branch.

These are acceptance limits. Existing complete-route JavaScript failures and missing real-device
evidence remain unresolved; shared policy support does not certify performance acceptance.

`timeScale` accepts finite non-negative numbers. `0` makes newly started or retargeted
recipes immediate (including springs and delays), while preserving the mode and its
target pose. It inherits through nested providers and can override a positive clock
on a nested provider or a single `cm.transition()` call. Negative and non-finite
clock values throw `RangeError`. Continuous CSS loops retain their theme clock.
Shared executors cancel existing owned writers at zero or a mode downgrade, including unchanged
targets. Finite positive action clocks stay captured; physics owners retime from current paint.
Other component/engine adapters still need their own adoption evidence.
