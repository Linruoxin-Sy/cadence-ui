## Tokens

Cadence does not ship its own color system. It reads the shadcn semantic tokens:

| Token | Used for |
| --- | --- |
| `--background`, `--foreground` | Page and default text |
| `--muted`, `--muted-foreground` | Quiet surfaces and secondary text |
| `--border` | Edges and dividers |
| `--primary`, `--primary-foreground` | Primary actions |
| `--destructive` | Destructive actions |
| `--ring` | Focus rings |

Override those variables the same way you would for any shadcn component. Everything in Cadence
follows, in both themes.

## Motion variables

`cadence-theme` derives CSS inputs and effective clocks from the shared motion source.
Tune authored durations through source variables:

```css
:root {
  --motion-source-duration-instant: 100ms;
  --motion-source-duration-fast: 160ms;
  --motion-source-duration-base: 220ms;
  --motion-source-duration-slow: 320ms;
}
```

CSS popup clocks and Motion resolve these inputs through the provider's inherited mode/timeScale.
The generated `--motion-duration-*` outputs retain their existing names. Explicit overrides of those
legacy outputs are already effective clocks and are not scaled again; source inputs are the preferred
way to tune a theme while retaining inherited scaling. None and zero recipe time still settle
immediately. Scope and portal transport preserve local class/style overrides; keep the generated
theme and provider source updated together.

Easing accepts cubic-bezier curves and standard CSS easing keywords. Spring duration/bounce,
distance, scale, rotation and stagger inputs are available in the shared parameter layer. Selecting
a size or text/number parameter does not install the corresponding controller or migrate a component.

Class/style and documented theme attributes, head stylesheet DOM/load changes, font loading and resize
refresh committed snapshots. After a CSSOM-only change, call `refreshCadenceMotionTokens()` from
`components/cadence/lib/motion-scope`. Other CSS-only state/media changes need that signal or a
committed owner update. There is no per-frame theme polling.

The JS presets live in `components/cadence/lib/motion.ts` and are the source of truth for durations,
easings, springs, and distances.

## Dark mode

Cadence follows the shadcn convention: a `dark` class on `<html>`. Set it before the page paints:

```html
<script>
  const stored = localStorage.getItem("theme");
  const dark = stored ? stored === "dark" : matchMedia("(prefers-color-scheme: dark)").matches;
  document.documentElement.classList.toggle("dark", dark);
</script>
```

## Motion modes

`CadenceProvider` accepts `mode`:

```tsx
<CadenceProvider mode="full">…</CadenceProvider>    // default
<CadenceProvider mode="reduced">…</CadenceProvider> // transform/scale dropped, timing ×0.6
<CadenceProvider mode="none">…</CadenceProvider>    // no animation
```

The OS setting `prefers-reduced-motion: reduce` always wins over `full`. The three modes, how
they resolve, and how to narrow one to a region: [Motion modes](/docs/motion-modes).
