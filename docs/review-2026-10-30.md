## 0. 一句话结论

工程骨架、元数据模型、按批次的文档组织是这套库最扎实的部分；真正的风险集中在**"声明的运动契约"和"实际实现"之间已经开裂**——
`button` 和 `dialog` 都声明了 recipe，但一行 `cm.transition()` 都没有真正调用，而现有校验脚本恰好查不到这一点。
同时文档站还停留在"能读"的阶段：没有搜索、没有目录、没有运动模式切换、每个页面把 29 个预览全部打进同一个客户端 bundle。

## 2. 运动契约合规审计（本次评审的核心发现）

按 `AGENTS.md` 的三条口径逐一核对：`registry.json` 的 `meta.motion`（声明）、`content/components/*.mdx`
的 `motion:` frontmatter（文档）、源码中的 `cm.transition("<recipe>")`（实现）。

| 组件       | 声明                          | 源码实际调用          | 结论                                                                                       |
| ---------- | ----------------------------- | --------------------- | ------------------------------------------------------------------------------------------ |
| `button`   | `feedback.press`              | **无**                | ❌ 用 CSS `transition-… duration-150 active:scale-[0.98]` 实现，`spring.press` 从未生效    |
| `dialog`   | `popup.anchored`, `exit.fade` | **无**                | ❌ 纯 CSS `data-[starting/ending-style]` + `duration-200/100` 字面量，两个 recipe 都无实现 |
| `skeleton` | `data.transition`             | 无（`animate-pulse`） | ✅ 合规：§3.2 连续式豁免                                                                   |
| `spinner`  | `data.transition`             | 无（`animate-spin`）  | ⚠️ 豁免成立，但 `animate-spin` 是 transform 循环，与 §3.2 规则 1「只允许 opacity」冲突     |
| 其余 25 个 | —                             | 与声明一致            | ✅                                                                                         |

### 2.1 `button`：声明与实现是两套东西

`registry/cadence/button/button.tsx:14,61-63`

```tsx
"… transition-[color,background-color,border-color,box-shadow,scale,transform,opacity] duration-150 ease-out …";
cm.reduced ? "active:scale-100" : "active:scale-[0.98]";
```

- 声明 `feedback.press`（`spring.press`，bounce 0.12），实现是 150ms CSS tween；
- 缩放值 0.98，而 `lib/motion.ts` 的 `scale.press = 0.97`（`toggle` / `toggle-group` / `slider` 用的都是 0.97），同一个手势两种数值；
- `content/components/button.mdx` 的 Motion contract 表写的是 `spring.press` —— 文档描述了一个不存在的实现；
- `transition` 属性列表里还挂着 `transform` 和 `opacity`，实际从不变化。

**两种修法，必须选一种并让三处一致**：

1. **走 Motion**（推荐，和 `toggle` 一致）：`render={<motion.button whileTap={cm.reduced ? undefined : { scale: scale.press }} transition={cm.transition("feedback.press")} />}`，
   同时从 `buttonVariants` 里删掉 `scale/transform`；
2. **走 CSS 并改口径**：把 recipe 改成 token 化的 CSS press（`duration-[var(--motion-duration-instant)]` + `ease-cadence-out` + `scale.press`），
   同步改 `docs/animation-system.md` §3 的 recipe 表、组件 MDX 和 `meta.motion`。

### 2.2 `dialog`：`none` 模式没有归零（P0）

`registry/cadence/dialog/dialog.tsx:35,61`

```tsx
cm.reduced ? "duration-100" : "duration-200";
```

`provider.tsx:27` 把 `reduced` 定义为 `mode !== "full"`，于是 `data-motion="none"` 落到 `reduced` 分支，
**仍然播放 100ms 的 opacity + scale**。这正是 `AGENTS.md` 第 3 条明令禁止的
"Mapping `none` onto the `reduced` branch is a failure"。

同时 `200ms / 100ms` 两个数字都不在 token 体系里（`duration.base = 220`、`duration.fast = 160`），
是 §2「Tokens only」直接违反。

**建议**：改用 §4 Pattern A 的 CSS 变量写法，把时长接到 token 上，并显式三态：

```tsx
const transitionClass =
  cm.mode === "none"
    ? "duration-0"
    : cm.reduced
      ? "duration-[var(--motion-duration-fast)]"
      : "duration-[var(--motion-duration-base)]";
```

或者退回 Motion（Pattern B）用 `cm.transition("popup.anchored")`，让 `exit.fade` 真正有落点。
无论哪种，`meta.motion` 必须跟着改。

### 2.3 建议把"连续式豁免"变成机器可读

`skeleton` / `spinner` 的"声明了但没调用"是合法的，但任何自动化检查都无法把它和 `button`/`dialog` 的真缺陷区分开。
建议在 metadata 里显式标注：

```jsonc
"motion": [{ "recipe": "data.transition", "form": "continuous" }]
```

这样 `check-registry` 就能实现：**声明了 one-shot recipe 却没有对应调用 = 失败；声明了 continuous 才放行**。
这是让 `AGENTS.md` 第 1 条从"靠人记"变成"靠 CI 拦"的关键一步。

### 4.2 性能：每个页面都在加载整座库

`components/site/preview.tsx` 是 `"use client"`，静态导入 `./previews`，而
`components/site/previews/index.tsx` 一次性 import 了 **29 个预览模块**（每个又 import 对应的 registry 组件）。
结果是：打开 `/components/button`，客户端会拿到全部 29 个组件 + 29 个预览 + Motion 的完整运行时。
这与 `animation-system.md` §7「Initial JS per page ≤ 120 KB gzip」直接冲突，而且会随 B4–B9 线性恶化。

**建议**：把 preview 映射改成动态的。

```tsx
// components/site/preview.tsx
const loaders = {
  button: () => import("./previews/button"),
  dialog: () => import("./previews/dialog"),
  // …
} satisfies Record<string, () => Promise<{ [k: string]: ComponentType }>>;
const Preview = dynamic(() => loaders[id]().then((m) => Object.values(m)[0]!));
```

或者更彻底：让预览走 RSC（不需要状态的预览完全可以服务端渲染），只有交互型预览进 client。

### 4.3 布局与导航

- **容器宽度不一致**：header 是 `max-w-5xl`（`header.tsx:7`），首页 `max-w-5xl`（`page.tsx:25`），
  但 components/docs 的 layout 是 `max-w-6xl`（`layout.tsx:8`）。从左栏顶部到 header 左侧，视觉上错开 48px。
  建议统一成一个 `--container-page` 宽度变量，header 和 content 共用。
- **侧栏 landark 噪音**：每个 batch 是一个独立 `<nav aria-label="Atoms">`，加上 Docs、header nav、breadcrumb，
  一个页面会出现 6–8 个 nav landmark。建议外层一个 `<nav aria-label="Documentation">`，batch 用
  `<h3>` + `<ul>`。
- **`aria-controls` 指向未挂载节点**：`Disclosure` 在关闭时 `return null`，但 header 的 `aria-controls` 仍指向那个 id，
  是无效引用（`aria-controls` 允许指向不存在元素在实践中会被部分读屏器忽略，但 axe 会警告）。
  要么保留 panel 挂载（`hidden` + `height:0`），要么去掉 `aria-controls`。
- **高度动画**：`Disclosure` 用 `cm.transition("reveal")` 动画 `height`（`sidebar.tsx` 的 `<motion.div>`），
  这是布局动画，而 `reveal` 是 tween —— 既不在 recipe 表里对应，也违反 §7「禁止触发布局」。
  建议换成 CSS grid-rows trick + `transform`，或明确在 animation-system 里加 `disclosure.height` recipe（parity-plan §6.3 早就计划了）。
- **缺 TOC**：组件页有 12–19 个标题，没有 "On this page"。这是长文档站最基本的可用性缺口。
- **缺 prev/next 与「Edit this page」**：29 个页面之间只能靠侧栏跳转。
- `lib/content.ts:128` 的 `guideOrder.indexOf(slug)` 对新指南返回 `-1`，新加的指南会排到 Installation **前面**。

| -------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |

| 「reduced 分支存在」= 文件里出现 `useCadenceMotion` 或 `data-motion`                                                                   | `dialog` 满足条件但 `none` 未归零                                                                           | 改成断言三态（见 §2.2），或交给 E2E                    |

### 5.2 缺失的验证层

`package.json` 里**没有 Playwright**，而以下位置都把它当作既有能力：

- `animation-system.md` §9.1（三层测试）、§9.3（契约断言）、§9.4（axe + 视觉回归）；
- `parity-plan.md` 的 batch gate（"manual `data-motion` full/reduced/none, axe, size budget, dual-theme screenshots"）；
- `overall-design.md` §11 的 Definition of Done；
- 每个批次的 §7.x 都以"截图未完成"收尾（B1/B2/B3 三次）。

结论：**"三种模式已被证明"目前只由 jsdom 断言支撑**，而 jsdom 不跑 CSS transition、不跑 Motion 的时间线。
这也是每次 batch 都无法真正关门的结构性原因。建议把 E2E 当作下一批次的前置，而不是尾巴。

### 5.3 单元测试的覆盖偏差

按 `AGENTS.md` 第 6 条（"asserts the `data-motion` value for each mode"）统计 `data-motion` 断言次数：

```
button 0 · dialog 0 · toggle-group 1 · progress 2
checkbox/input-otp/skeleton/slider/spinner/switch/toggle 3
其余 19 个文件 0（T0，合理）
```

**恰好是两个有缺陷的组件（`button`、`dialog`）没有任何 mode 断言**——这不是巧合，是"测试跟着实现写"而不是"测试跟着契约写"的结果。
建议把断言做成共享 helper：`expectMotionContract(renderFn, { modes, dropsTransform })`，新增组件必须调用。

### 5.4 流程性不一致

- `dialog` 的 `meta.batch = "B4"`，但 `parity-plan.md` 的 B4 行仍是 `next`。按 §7.0 自己的规则，
  一个批次里的组件已经上线、批次却标 `next`，属于流程缺陷。
- `meta.intensity` 29 个组件里 28 个是 `subtle`（只有 `dialog` 是 `medium`）。设计文档把 intensity 当作筛选维度，
  实际它没有区分度。
- `content/docs/validation.mdx` 写「Wires `aria-describedby` / `aria-errormessage` to the ids of the elements it renders」，
  但 `registry/**` 里没有一处 `aria-describedby`（唯一出现是 `field.tsx:202` 的注释）。
  组件文档是对的（把 id 接线交给用户），指南把责任说反了。
- `docs/animation-system.md` §5 的 `Recipe` 联合类型包含 `theme.reveal`，`lib/motion.ts:34-51` 里没有；
  §2.2 的 `ease.spring` 在 `motion.ts` 里也不存在；§2.3 的 `--motion-intensity: 0.5` 与 `globals.css:131` 的 `0.6` 不一致。

## 7. 值得保留的部分

评审不是只挑毛病。以下设计在同类项目里属于上乘，改动时不要顺手破坏：

1. **源码树镜像安装树**（`registry/cadence/<id>` ↔ `components/cadence/<id>`）——零 AST 重写，`../lib/motion` 装完仍成立，这是整套方案最聪明的一条。
2. **`registryDependencies` + 同 target 去重**，而不是像 Arc 那样内联复制源码——payload 小、不会漂移。
3. **P11 是可执行的**：依赖黑名单 + import 正则 + 文档表格三层一致，比"写在 README 里"强得多。
4. **`upstream/manifest.json` 离线 pin + additive 只报告不失败**——既守住 P8，又不阻碍有意增强。
5. **`meta.batch` 同时驱动构建顺序与侧栏分组**——一个字段解决两件事，`lib/content.ts` 里那句"empty batches dropped"很干净。
6. **文档正文内嵌进 payload**（`docs` 字段），MCP/CLI 一次请求拿到源码+文档。
7. **T0 明确不引入 motion 运行时**，并且把这个"偏离"写进了 `parity-plan` §7.1——该省的地方省了，而且有记录。
