# Code Block motion contract

Status: target design; implementation and verification pending.

Code Block keeps code readable while explaining folding, active-file changes and copy feedback. Its actual Header/Title/Tabs/Tab/Actions/CopyButton/Content/Panel/Line/Footer/ExpandButton parts remain intact. A code edit animates only changed graphemes or safe shaping runs; syntax colouring is presentation, not the identity of source text.

Use the [shared contract](../README.md) and [preset definitions](../presets.md). The target preserves native `pre`/code selection, the current tab API, controlled expansion and exact copy semantics.

The grouped `surface.colour` binding includes the named `code-block-tab-indicator` background rendered by CodeBlockTab. Its paint is separate from the tab button's foreground and `indicator.select` geometry. This adds neither a second selected background on the button nor a second colour controller on the marker.

CopyButton and ExpandButton retain the existing Button surface/foreground owner, including paint supplied by the floating-actions cascade; `surface.colour` never adds a second CSS colour writer to those controls. ExpandButton's known label region uses the one `text.replace` owner and consumes duplicate Button processing for that same content. CopyButton's direct primitive display child keeps Button's string/quantity handling; arbitrary rich children remain composed and are not scanned. Its local icon action applies only to the actual default glyphs, while accessible copy-status text commits immediately. Initial controls share their surrounding presence; later independent control membership uses the surviving Button presence owner. Same-cause control/parent geometry uses committed destinations or delegates that axis, never a second spring following interpolated button size.

## Interruption and lifecycle

- Rapid fold reverses from current viewport size. Rapid tab selection moves the same marker to the latest active panel without remounting unrelated panels or replaying the whole code block. Persisted panels retain their own source/scroll state; do not diff two different files merely because the active tab changed. First marker placement or a restored selection without a valid previous tab is immediate.
- Diff the direct source string, not highlighted span keys/classes or line indices. A one-character change cannot fade its entire retained line. A newline insertion/deletion may split or join lines while most glyphs survive: retain those glyphs across the old/new line boundary, and use whole-line entry/exit only for units with no retained identity in the revision. If bounded diff cannot establish safe identity, commit the affected source immediately rather than treating unmatched lines as entirely new.
- Syntax grammar loading, language changes, theme/token recolouring and asynchronous highlighter results are presentation revisions, not source edits. Tag their result with the current source/language revision, discard stale results and preserve source identities across token boundaries where mapping is safe. Unsupported token/shaping mappings use immediate final paint with no whole-source crossfade.
- Preserve one current accessible and selectable source tree; outgoing fragments are aria-hidden, nonselectable, noninteractive and excluded from intrinsic sizing. CodeBlockCopyButton continues to copy its explicit value or values[current tab] contract, never innerText from animated/highlighted DOM; a missing tab mapping does not copy another tab. During native selection that intersects changed code, suppress replacement visuals for that scope without rewriting Selection ranges; unchanged nodes and caller editors remain intact.
- Copy success/error timing remains existing semantic feedback, not an animation timer. Bind any asynchronous clipboard result and its visual completion to the activation's captured text and current button lifetime; a result from an old tab/source cannot claim that the currently shown source was copied or restart its feedback. Tab buttons retain their actual native selection semantics; the inherited Button press binding covers CopyButton and ExpandButton only. Close/unmount cancels active source/geometry/indicator writers and measurement. Reopening does not replay previous copy or code changes.
- Live reduced settles viewport, tab-marker, retained-unit movement and expand-chevron geometry immediately and removes copy-icon scale/reels. Permitted changed-run/line, copy-icon and action opacity and eligible colour reconcile under their reduced contracts; real focus/selection still takes priority. None or zero recipe clock settles all one-shot work to the effective mode's current target before paint. Positive clock edits follow each preset's capture-or-retime policy, without creating a copy/source revision or replaying settled work.

## Geometry and performance

Measure natural `code-block-content`/code layout separately from the clipped viewport. Folded height respects actual line-height/padding and `maxLines`, with SSR reservation and no-JS readability preserved. Lay code out at destination inline-size before animating only the viewport block-size; do not continuously rewrap or scale glyphs. A distinct newly active Panel viewport takes its final measured size rather than animating from a hidden zero measurement or another panel's old height. A surviving composed ancestor may own a cross-panel height transaction, in which case the child viewports do not animate that same cause. Width, scrollbar positions, passive font/viewport changes and native horizontal scroll resolve immediately. Clip code paint only, preserving action focus outlines and functional scrolling.

For a large source, inspect only the bounded affected visible lines/runs needed for the current revision. Automatic line presence/layout counts participating line presentations, any measured/projected retained lines, distinct outgoing visuals and a participating collection shell under the [collection bound](../presets.md#52-shared-work-limits), before member layout reads or retained-copy allocation. A whole-block envelope counts once, not once per syntax token or glyph. The shared diff-work and aggregate changed-glyph/reel limits apply once to the whole block revision, not once per line or token. Avoid re-tokenizing solely for animation, per-glyph layout reads, hidden full-document clones and work on every persisted inactive panel. Newline/duplicate-line ambiguity or a working set that cannot fit uses immediate affected source/layout, without truncating the file or queuing later batches. Nested parent geometry adopts the committed destination rather than chasing every height frame.

## Acceptance scenarios

- Pending: edit one character, insert/delete a line, change syntax-token boundaries and supply unsafe rich token content; unchanged source remains still and fallbacks stay exact.
- Pending: fold/reverse, switch differently sized tabs rapidly, change maxLines and close the parent mid-motion; viewport/indicator end at the latest semantic target.
- Pending: copy during source replacement, select text across changed lines, use line numbers/wrap/highlights and keyboard-focus actions; copied and accessible source contain no stale fragments.
- Pending: verify SSR folding/no-JS readability, all modes, high-frequency updates, live downgrade, zero clock and unmount without retained measurement or visual layers.
- Pending: split/join a line, insert above repeated identical lines, resolve an old highlighter promise after a newer source/language change, and switch tabs mid-copy. Retained glyphs never receive whole-line fades; copy follows the explicit current value map and grammar/theme changes do not masquerade as source edits.
- Pending: start two clipboard requests for different tab/source values, resolve the older request last, then unmount/reopen. Only the matching current activation may update its feedback; a rejected/cancelled click creates no motion-only copied state.
- Pending: select across a changing line, exceed aggregate diff bounds, update an inactive persisted panel, and activate a differently sized panel without a shared host. Source/selection stays exact, work stays bounded, and no hidden zero height or synthetic cross-file diff becomes visible.

- Pending: change the active marker's theme/background while selecting another tab and focusing its button. The marker has one declared paint owner separate from its geometry; the focused button's paint settles immediately without replaying unchanged label text or adding a second selected surface.

- Pending: change floating-action colours while focusing CopyButton/ExpandButton, and provide plain, numeric and rich CopyButton children alongside an updated ExpandButton label. Each control keeps one inherited Button colour owner, focus/invalid paint is immediate in full/reduced, and custom content never acquires duplicate text/reel or default-glyph effects.
- Pending: reduce during a fold/marker/chevron change plus safe source-run, copy-icon and action opacity. Geometry and icon scale settle immediately while drawable permitted paint follows reduced mode; compare none/zero and a positive clock edit without replaying source, clipboard feedback or settled tabs.
