## Conclusion and obligation boundary

All listed exports are reviewed for finite prop/render/ref/event/context compatibility;
no production defect was found and no shipped source, classes, recipes, dependencies,
DOM structure or interaction implementation changed. Transparent rest forwarding plus
installed types and applicable existing tests support the simple native/Base paths;
new tests target actual composition/ref/ownership risk rather than mirroring each div.
Button's prior bounded compatibility status is now reviewed-compatibility: earlier
four-event/cancel/render/ref/identity/controlled/keyboard/form tests and unchanged
adapter source satisfy these finite obligations. Its live mode/clock and disabled
visual cancellation remain independently OPEN, not an indefinite compatibility blocker.
Toggle/Group remain outside this group with their historical bounded classification.

Native ComponentProps and native useRender.ComponentProps expose string className /
object style; they do not gain Base state callbacks from using useRender internally.
Only Button, Input, Avatar Root/Image/Fallback, Separator and wrappers actually inheriting
those types expose Base callback classes/styles; InputGroupInput deliberately declares
native input props. Both Base render forms delegate to installed useRenderElement;
element own props compose after component props, with refs merged separately via
useMergedRefs. mergeProps itself does not merge refs. preventDefault cancels native
default; preventBaseUIHandler owns Base handler veto. Render functions are caller owned
and must spread the actual evaluated props including ref (new fixtures do so). No
unbounded permutations of arbitrary caller render implementations are required.

There are no exported provider/context symbols in these twenty items. Avatar Base
context, shared motion context, Card measurement refs and CSS-only group relationships
are distinguished in the rows. Types and CVA helpers own no DOM and are reviewed-static.
KbdGroup's div-derived props/actual kbd and EmptyDescription's p-derived props/actual div
retain pinned upstream behavior rather than silently changing public types/markup.
